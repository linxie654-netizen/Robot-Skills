## UAS 授权：哪个操作要哪个授权（2026-11-21 从 ABB RAPID Pack 公开文档学）

| 想干什么 | 要什么授权 |
|---|---|
| 读控制器、RAPID、I/O 状态 | 有读权限的 UAS 账号 |
| 写 RAPID 变量当前值 | `UAS_RAPID_CURRVALUE`，还要 mastership 和控制器状态允许 |
| 启动/停止/复位 RAPID | `UAS_RAPID_EXECUTE`，还要运行状态允许 |
| 加载/卸载/部署模块 | `UAS_RAPID_EDIT`、`UAS_RAPID_LOADPROGRAM`，还要 mastership 和文件服务权限 |
| 读/写控制器文件 | `UAS_FTP_READ` / `UAS_FTP_WRITE` |
| 写 I/O 信号 | `UAS_IO_WRITE`，还要信号的自动/手动访问级别允许 |
| 新建 I/O 信号 | `UAS_CFG_WRITE`，还要配置 mastership |
| 热启动 | 重启授权 |
| 设控制器断点 | `UAS_RAPID_DEBUG`，还要 mastership |

- 写操作被拒先查四道门：工作区受信任、配置是 Read & Write、写/执行总开关开了、当前连接的写权限已激活；再查 UAS 授权、运行模式、mastership。

## 配 IO 信号（2026-11-21 从 R1 段 9 草稿学）

- 问题：信号怎么配、程序里怎么用？
- 答案：信号分四种：DI（传感器、按钮发来的 0/1）、DO（机器人发出去的 0/1）、AI/AO（连续量）；组信号 GI/GO 是几个数字信号拼成一个数，PLC 发程序号就用组信号。配在控制器 Configuration Editor 的 I/O System 里：新建信号，定名字、类型、接哪个设备；程序里用的名字必须和配置里一模一样，差一个字母就报错。程序里：SetDO 发 1/0（Reset 是置 0），WaitDI 等输入变 1，WaitUntil 等条件成立；等信号要加超时，一直等不到就报错。没设备时在示教器 Inputs and Outputs 里把信号设成模拟，手动拨 0/1 调程序；记得取消模拟。新建信号要 UAS_CFG_WRITE 授权和配置 mastership。
- 为什么：信号名是控制器配出来的，不是程序里随便起的；名字对不上编译就报错。
- 信号配好还得接东西：仿真里信号要起作用，得配 Smart 组件——组件里加对应的输入/输出信号，把控制器信号和组件信号连起来；RAPID 发 SetDO，组件收到就动；组件的输出回给 RAPID，用 WaitDI 等。夹爪的例子：控制器配 doGrip，组件里配 diClose，doGrip 连到 diClose 上，不然 SetDO 发出去没东西响应。真空夹爪是 DI_Attach 控制吸放，传感器碰到箱子吸住，DI 撤掉（过 NOT 门）放开。只写程序不跑仿真可以不配组件；要仿真跑通就得配。

## 进阶三课：EGM、多任务、外轴（2026-11-22 用户点直接学难的，写进 docs/advanced-topics.md）

- 问题：EGM 是什么、怎么用？
- 答案：EGM 是电脑每 4 毫秒发一次位置、机器人跟着走的实时控制，分位置引导（电脑定路）和路径修正（程序定路、电脑只发偏移量）两种；要开 689-1 选项、配 UC 通讯、电脑同时跑发数据的程序。RAPID 例程四步：EGMGetId 领身份证 → EGMSetupUC 配通讯 → EGMActJoint 准备会话 → EGMRunJoint 开始跑；电脑断了报 ERR_UDPUC_COMM。三种模式：关节目标（发 6 个关节角，最简单）、姿态目标（发位置+四元数，要躲奇异点）、路径修正（发路径坐标偏移，48 毫秒才更新一次）。
- 为什么：EGM 绕过路径规划和很多安全功能（包括防碰撞），先在仿真里测；光写 RAPID 不够，电脑不发数据程序就卡在等 UDP 包。

- 问题：多任务是什么、任务之间怎么同步、怎么共享数据？
- 答案：一个控制器同时跑几个 RAPID 任务，各干各的活。开 623-1 选项；任务分三种类型：NORMAL（机器人运动任务，只能是这个，急停会停）、STATIC（后台跑，急停也不停）、SEMISTATIC（后台跑，开机自动从头跑）；调试先全用 NORMAL，调好再改回去、重启控制器。同步用 WaitSyncTask（各任务跑到碰头点一起等，人齐再走）；共享数据用 PERS 变量放公共模块（所有任务都加载）或用信号。两台机器人配合用 MultiMove：604-2 独立（各干各的、只在碰头点等）、604-1 协调（全程同步，包含独立的全部功能）；协调动作包在 SyncMoveOn / SyncMoveOff 里，每句 Move 带 \ID，两台机器人 \ID 一一对应。
- 为什么：一个控制器最多带 4 台机器人、最多 7 个运动任务（产品规格原话）；后台任务急停不停，写的时候要想清楚急停后它该干什么。

- 问题：外轴是什么、怎么编？
- 答案：外轴是机器人本体六个轴之外的轴，常见变位机（翻工件）和导轨（带机器人走）。动外轴前先 ActUnit 激活机械单元（名字按自己系统的改）；只动外轴用 MoveExtJ；robtarget / jointtarget 里的 extax 是外轴位置，写 9E9 表示“这根轴别管”。变位机翻 90 度再焊的例程：ActUnit → 焊第一面 → MoveExtJ 转 90 度 → 焊第二面。协调运动两种做法：工件坐标系挂变位机上，或机器人和变位机各一个任务、用 SyncMoveOn 包起来。
- 为什么：外轴不标定，转的角度和程序里的角度对不上；点位教的时候外轴在 0 度、跑的时候在 90 度，点位全错；外轴动起来力气大，翻工件时人在单元外。

## ABB 坐标与六个轴、直线走不通怎么办（2026-11-22 Q90，从 IRB 120 手册和 Three.js 演示学）

- 问题：RobotStudio 里坐标轴是怎么指的？六个轴各管什么、转多大？
- 答案：ABB / RobotStudio 的规矩是 X 前后、Y 左右、Z 上下（Z 朝上），跟画 3D 常用的 Y 朝上不一样；三套坐标系要分清——大地（世界）坐标、基坐标（机器人底座）、工具坐标（装在法兰上，跟夹爪一起动），点动时先选在哪套坐标系里走。六个轴按 IRB 120 手册：J1 ±165° 旋转（转底座）、J2 ±110° 大臂、J3 -110°~+70° 小臂、J4 ±160° 腕部旋转、J5 ±120° 腕部弯曲、J6 ±400° 法兰旋转。注意 J3 正向（前臂往前弯）最多只到 70°，前臂弯不到水平。
- 为什么：点动时按错坐标系，机器人走的方向跟想的完全不一样；J3 只有 70° 意味着截图里那种前臂水平的姿势IRB 120 本体摆不出来，示教点位时别往那个方向硬够。

- 问题：MoveL 直线走不通，报到不了，怎么办？
- 答案：先想想是不是要换个构型：同一个末端点，机器人可以用好几种姿势够到（肘部往这边弯还是往那边弯、腕部翻不翻），这叫构型。直线（MoveL）只能在当前构型里走，换构型得先走关节（MoveJ）过去，再走直线。演示里试过：点 (0.30, 0, 0.60) 直线走不通，换了肘部翻面的姿势（J3 从 +70° 变 -84°）就到了。
- 为什么：逆解是局部算的，从当前姿势出发、一步步往目标挪，构型翻面那一步它自己跨不过去；关节角到限位（J1、J3、J5 都顶到头）时也一样，剩下的关节再怎么转也够不着，报到不了是老实话，不是算错了。

## 位置和姿态一起控、点动与示教（2026-11-22 Q91，从 Three.js 演示学）

- 问题：末端位置和姿态怎么同时控制？只改位置、姿态不动怎么做？
- 答案：位置 XYZ 和姿态 RX/RY/RZ 一起输，逆解要同时解 6 个数（位置 3 个 + 姿态 3 个），这叫 6 自由度逆解；只改位置、姿态不动时，姿态目标就填当前姿态，逆解会一边挪位置一边把姿态 hold 住。姿态用欧拉角表示：绕 X 转 RX、绕 Y 转 RY、绕 Z 转 RZ，顺序是 Z-Y-X；RobotStudio 里看姿态也是这三个角。演示里试过：位置 (0.35, -0.05, 0.60) + 姿态 (20°, 10°, -15°) 一次到位，位置差 1.5mm、姿态差 0.0°。
- 为什么：只解位置的逆解不管姿态，末端到了、夹爪朝向可能歪了；姿态和位置一起解才算真的重定位。姿态角也有到不了的时候（比如腕部翻不过去），那时报到不了、姿势不动，是老实话。

- 问题：线性点动怎么保证 TCP 走直线？步进距离怎么选？
- 答案：点动不是一次跳过去，是每步都重新逆解一小步（1mm、5mm、10mm、20mm、50mm 选一个），步步都落在目标轴上，连起来就是直线。步进越小越准、越慢；步进越大越快，但一步跨太大逆解可能跟不上。演示里五种步进 X+ 全准，Y/Z 不动。
- 为什么：一次跳 50mm 和分 50 次走 1mm，末端走的路不一样；小步多走是拿时间换精度。按住连续点动就是一直重复小步，松开就停。

- 问题：示教时怎么知道机器人现在在哪、姿态对不对？
- 答案：看监控：TCP 的 XYZ（米）、RX/RY/RZ（度）、六个关节角（度），都是实时从关节角算出来的，不是手填的。动一下滑块、点一下点动，监控马上跟着变。轨迹是把 TCP 走过的点连成线；记录是把关节角序列存下来，回放就是按存下来的关节角原样走回去。
- 为什么：监控和轨迹都是结果，不是输入；输入错了、逆解歪了，监控马上露馅。回放按关节角走比按 TCP 位置走更准，因为关节角就是机器人真正的姿势。

## 重定位点动与关节限位（2026-11-22 Q92，从 Three.js 演示学）

- 问题：线性运动和重定位运动到底有什么区别？为什么不能把重定位做成另一种线性运动？
- 答案：线性是 TCP 平移——末端沿一条直线挪位置，姿态尽量不动；重定位是 TCP 原地转姿态——末端位置钉在原地不动，只绕工具坐标轴转 RX/RY/RZ。两个的逆解目标不一样：线性只给位置目标，重定位只给姿态目标、位置目标就是当前位置。演示里点 RX+ 5°，TCP 只漂 1.3mm、姿态转了 5.0°，这就是重定位；点 X+ 20mm，TCP 沿 X 走了 20.4mm，这就是线性。效果上必须一眼分得清。
- 为什么：示教器上这是两个不同的操作意图——挪位置是去够一个点，转姿态是调夹爪朝向；混在一起，操作员就不知道按下去末端会平移还是会转。IRB 120 本体器人上也是这么分的。

- 问题：重定位点动是怎么转的？TCP 怎么保证不动？
- 答案：一次点动（比如 RX+ 5°）先拆成 ≤2° 的小步，每小步用 6 自由度逆解算六个关节角，位置目标全程都是起点 TCP、姿态目标每次往前挪一小步；步进有 1°/5°/10°/30° 四档，按住就一直转、松开就停。演示里 1° 步进转了 0.98°、30° 步进转了 30.0°，TCP 漂移都在 1.6mm 以内。
- 为什么：大角度一步到位逆解容易算不准、还容易撞限位；拆小步是拿步数换稳定，每步都重新把 TCP 钉回原地，漂移就攒不起来。

- 问题：重定位转不过去的时候怎么办？怎么知道是哪根关节卡住了？
- 答案：转到哪算哪——某小步转不过去就停在那，不回退；再点就报“转不过去：J3要到71.4°（上限70°）”，直接点名卡住的关节和要到的角度。演示里回零位 RY+ 转不过去就是 J3 顶着（回零位 J3 已经在 70° 上限），把 J3 收到 60° 再转就过去了。转不过去不是程序坏了，是姿态真到不了，姿势不动、报清楚原因就是对的。
- 为什么：回零位同时顶着两根限位——J1=165°（上限 165°）、J3=70°（上限 70°），往哪个方向转都要先看这两根让不让。报错点名关节，操作员就知道该把哪根关节先收回来，而不是对着屏幕干瞪眼。

- 问题：线性点动默认用哪个坐标系？基座和世界不是重合的吗，为什么还要分？
- 答案：默认基座坐标系（ABB 常规操作），世界和工具也能切。基座现在和世界重合、方向一样，但它是独立的坐标系：机器人挪了位置，基座跟着走、世界不动；点动方向按基座算，机器人挪窝了点动方向还跟得上。演示里基座 X+/Y+ 各走 20mm，工具 Z+ 沿当前夹爪方向走 20mm（转完姿态再点，方向跟着新工具 Z 走）。
- 为什么：世界是场地不动的参考，基座是机器人自己的参考；两个重合只是现在这个摆法，概念上不能混。工具坐标系是夹爪自己的，姿态一转、工具轴就跟着转，点动方向也跟着变。

## 控制面板与视角（2026-11-22 Q93，从 Three.js 演示学）

- 问题：示教界面怎么摆，操作的时候才能一直看见机器人？
- 答案：3D 画面和控制面板不能上下叠着摆——面板在下面，人一滚下去点按钮，机器人就滚出屏幕了。电脑上左右分栏：3D 在左钉住不动，面板在右滚动；手机上 3D 吸顶，一直钉在顶上，面板在下面滚。演示里改完：桌面往下滚 1200px，机器人还在左边；手机往下滚 1500px，机器人还在顶上。
- 为什么：示教是边看边点的活，眼睛不能离开机器人；画面一滚走，人就不知道自己刚才点动的效果对不对。视角也要能一键回正（拖乱了点【视角复位】就回来），不然转着转着就找不着机器人了。

- 问题：操作说明怎么写，用户才真的会点？
- 答案：别写一大段说明，没人看。三步就够：①选模式（轴关节/线性/重定位），②怎么动（拖滑块、点 X+/Y+/Z-、点 RX+/RY+/RZ-），③边点边看。长的坐标和验证说明收进折叠里，想看再点开。
- 为什么：用户打开页面是来动机器人的，不是来读说明书的；三步能上手，细节等他问了再讲。

## ABB 官方 RoboMasters App 学到的（2026-11-22）

- 问题：ABB 官方的学习 App RoboMasters 教什么？
- 答案：5 门课：IRC5 Operator、IRC5 Basic Programming、OmniCore Operator、OmniCore Basic Programming、Advanced Programming。从安全、手动点动、示教器用法，一直讲到错误处理、TRAP 中断。课程按 ABB 全球统一培训大纲做，一门课拆成二十来个小活动。免费层只有入门指南和小技巧；正课要订阅，Basic 一年选 1 门，Premium 一年全开，要注册账号。
- 为什么：知道官方怎么排课，我们的路线就能对上官方的岗位分法：操作员先学会动机器人、看报错、备份；编程员学 RAPID；进阶学系统事件、中断、搜索、触发。

- 问题：对照官方 Advanced Programming 大纲，我们漏了哪些知识点？
- 答案：漏了 5 个：① Event Routine：开机、启动、停止、复位时自动跑的例行程序，在系统参数 Controller → Event Routine 里挂；② SearchL：沿直线走、等信号变化、记下当时位置，用来找工件；③ AccSet / VelSet：限加速度、限最高速度，搬易晃的东西用；④ TriggIO + TriggL：走到路径上某个位置就触发 IO，不用停下来再 SetDO；⑤ ConfJ / ConfL：姿态监控开关，关掉后机器人可以换腕部姿态，代价是姿态可能突然翻转。另外 UAS 用户授权和事件日志我们也没专门讲。已补进 `docs/beginner-roadmap.md` 的 L16–L20。
- 为什么：官方高级课把这些当成会编程的门槛；用户以后去考 ABB 证书、看别人的程序，都会碰到。

- 问题：官方 App 的教法哪些值得学？
- 答案：三样。① 课拆小：一个活动几分钟，碎片时间能学一个；② 闯关：互动课 → 仿真 → 挑战，学完马上动手，过关给分；③ 单元结业：一个单元里的模块全部通过才发证，看完不算。我们照这个做：每课一个小挑战，在 RobotStudio 虚拟控制器里跑通才给分；一个单元全过才算结业。做法写在 `docs/teaching-guide.md` 第十二节。
- 为什么：用户在手机上用过，觉得这样学得进去。游戏化让人愿意接着学，单元结业让“会了”有个硬标准，跟我们每课的“算会”是一个意思，只是更明确。
