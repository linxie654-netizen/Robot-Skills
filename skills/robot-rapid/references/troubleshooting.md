# 报错排查手册 — Robot-RAPID

先走四步，再动手改：**1 复现**（在哪一步、什么操作、原样报错贴出来）→ **2 定位**（先查下面这张表，报错先对号，不猜）→ **3 修**（一次只改一处，改完再跑）→ **4 验证**（仿真里跑通、查完碰撞，才算修好）。没跑通就别说修好了。

## 报错对号表

| 现象 / 报错 | 先查什么 | 怎么办 |
|---|---|---|
| 目标点不可达 / 机器人够不着 | 手腕姿态（config）和工件坐标系（wobjdata） | 先查这两处，别乱改点位；换个姿态或重设工件坐标系再试 |
| 读模块报 C0049004 | 控制器里有没有装 RAPID 程序 | 控制器没装程序，先装 `rapid/01_move_basics.mod` 再读 |
| RWS 文本端点 404 | 是不是走了 RWS 文本端点 | 模块端点不匹配是已知问题，改走 `/rw/rapid/modules?task=T_ROB1` |
| 浏览器打开控制器地址看到 401 | RWS 是不是通了 | 401 是正常的，说明 RWS 通了、只是要登录，别当故障 |
| 新建虚拟控制器失败 | 本机 RIM 层故障 | 不要反复重试；克隆已有系统，或在界面里手工建 |
| 工作站被锁、打不开 | `RobVC.exe` 还在跑 | 关 RobotStudio 时连 `RobVC.exe` 一起杀掉 |

## RAPID 代码本身常犯的错（2026-11-21 从 ABB RAPID Pack 公开文档学）

编辑器/扩展的报错提示能帮你抓这些，先对号再改：

- 类型不匹配：标量声明、赋值、函数返回值、条件、循环、数组下标、`TEST` 的值
- 参数不对：用户例程的参数个数和类型、可选参数顺序和替代写法、开关
- `VAR` / `PERS` / `INOUT` 访问模式用错
- 未知的记录成员、对原始值取成员
- 往常量里写值、常量/字面量初始化写错、数组维数不对、重复声明、块放错位置、return 写错

严格检查（未解析的变量、跨文件重复的全局量）容易误报，因为控制器自带的数据不一定在源码里；新手先开基础诊断，熟了再开严格的。

诊断过了不等于控制器认了，部署前必须过 RobotStudio 的 Check Program。


## 反模式：写错了的程序长什么样、怎么认出来

报错对号表是事后查，下面的反模式是事前别写。每条四句：名、错法、认法、改法。

1. **MoveL 一路用 fine**：错法是每句 MoveL 都写 fine；认法是轨迹一段一段顿、节拍慢；改法是过渡点用 z50/z100，只有停下干活的点用 fine。
2. **回零该用 MoveAbsJ 却用 MoveJ**：错法是回零写 MoveJ pHome，姿态可能绕远路；认法是回零时手臂姿态不对、转大圈；改法是回零用 MoveAbsJ 写六个关节角，姿态定死。
3. **IO 不等信号就往下走**：错法是 SetDO 合爪后马上 MoveL，不等夹紧信号；认法是偶尔抓空、工件掉；改法是合爪后加 `WaitDI diGripOk, 1;` 再走。
4. **点位抄教学值不重示教**：错法是例程点位直接跑；认法是抓空、撞工件；改法是点位是教学值，仿真里重示教。
5. **所有动作堆在 main 里**：错法是取、放、回零全写在 main 里；认法是改一处要翻全篇；改法是取、放、回零各一个子程序，main 只做调度。

## 排查时要问用户的三句话

1. 报错原话贴出来（截图或复制，别只说“报错了”）。
2. 卡在哪一步：建站、加机器人、教点、仿真、还是下程序？
3. 上一次能跑的时候，改过什么？一次只改一处。
